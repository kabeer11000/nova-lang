01Whitespace

pattern: [ \t\r\n]+ — discarded, produces no token

stateDiagram-v2
    state "InWhitespace (SKIP)" as InWhitespace
    [*] --> InWhitespace : WS/NL
    InWhitespace --> InWhitespace : WS/NL
stateclasstargetaccepts
StartWHITESPACE, NEWLINEInWhitespace—
InWhitespaceWHITESPACE, NEWLINEInWhitespace (self)—
InWhitespaceeverything elseDEADSKIP

Anything besides whitespace or a newline from InWhitespace is dead, which is exactly what makes it accept SKIP. Only family that treats those two classes the same — comments (02) split them apart again.

Hitting a newline or EOF while in InLineComment is dead too, same accept-SKIP deal. AfterSlash has to accept Slash by itself, since a lone / is just division — there's no way to know it's a comment until the next character shows up.

03Integer literal

pattern: [0-9]+

stateDiagram-v2

    [*] --> InInt : DIGIT
    InInt --> InInt : DIGIT
stateclasstargetaccepts
StartDIGITInInt—
InIntDIGITInInt (self)—
InInteverything elseDEADIntLit

Anything that isn't a digit is dead, so it accepts IntLit. Simplest family by a wide margin — one state, one self-loop. No sign, no decimal point, no hex, matching how SPEC.md defines integers.

04Identifier / keyword

stateclasstargetaccepts
StartALPHA_InIdent—
InIdentALPHA_, DIGITInIdent (self)—
InIdenteverything elseDEADIdent

Same idea — anything that's not a letter, digit, or underscore is dead, and it accepts Ident. Keywords don't get their own states here; fn and foo look exactly the same to this diagram. The keyword check happens afterward, a plain lookup against a list once the identifier's already matched.

05String literal + escapes

pattern: '"' ( '\' any | any-except-["\] )* '"'

stateDiagram-v2
    state "InString (not accepting)" as InString
    state "InStringEscape (not accepting)" as InStringEscape
    state "StringDone (StringLit)" as StringDone
    [*] --> InString : QUOTE
    InString --> InString : not QUOTE/BACKSLASH/EOF
    InString --> InStringEscape : BACKSLASH
    InStringEscape --> InString : any char, even QUOTE
    InString --> StringDone : QUOTE (real close)
    StringDone --> [*]
stateclasstargetaccepts
StartQUOTEInString—
InStringeverything but QUOTE, BACKSLASH, EOFInString (self)—
InStringBACKSLASHInStringEscape—
InStringEscapeeverything but EOFInString—
InStringQUOTEStringDoneStringLit
InString / InStringEscapeEOFDEADnone — unterminated string error

Hitting EOF while still in InString or InStringEscape is dead with nothing accepted, which triggers the unterminated-string error. Also the only family that stays non-accepting for two states in a row. InStringEscape sends everything back to InString no matter what character shows up, quote included — that's the whole reason \" doesn't close a string early.

09Bang / NotEq

pattern: "!=" only — bare ! is not a Nova token

stateDiagram-v2
    state "AfterBang (NOT accepting)" as AfterBang
    state "NotEqDone (NotEq)" as NotEqDone
    [*] --> AfterBang : BANG
    AfterBang --> NotEqDone : EQUALS
    AfterBang --> [*] : else -> LEXICAL ERROR
    NotEqDone --> [*] : else -> accept NotEq
stateclasstargetaccepts
StartBANGAfterBang—
AfterBangEQUALSNotEqDone—
AfterBangeverything elseDEADnone — "unexpected character '!'"
NotEqDoneeverything elseDEADNotEq

AfterBang is the only intermediate state in the whole table that's deliberately not accepting. Nova spells negation with the not keyword, so this state exists purely to let != through and reject a bare ! for anything else.

★ UNION — ALL 15 FAMILIES SHARE ONE START

Every diagram above starts at Start, so laying them all on top of each other at that one shared node is literally the whole machine — nothing extra added:

No two families use the same character class coming out of Start, so they all fit together with no conflicts. Expand each box here back into its full set of states and this is exactly the 40×29 table in dfa_table.csv, just drawn instead of dumped as text.
